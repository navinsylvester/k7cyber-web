# Field
One labelled form control: an underline in `ink` that turns `signal` on focus and `acc-ink` on error (after a refused submit, `is-invalid`, or once the browser itself finds the value invalid, `:user-invalid`), with the label above in mono and the error below.

**Use** for every input, select and textarea in enquiry, demo, quote, partner and contact forms. Group fields in `form-grid` (two columns from 520px, one below); span the message with `span-2`. Checkboxes are `check`: an 18px square that fills `signal` when checked.

**Provide** `id`, `label` (mark required fields with * after the label, the asterisk alone in the accent as `<span class="req"> *</span>`, and say "Fields marked * are mandatory" once above the form, `req-note`, with the same accent asterisk), `type`, placeholder, value, and the error text. Selects get `control is-select` for the chevron. Country defaults to India; State defaults to "Select a State".

**The open list** (since 2026-11-21): every select's list, on the site and both portals, is drawn in the language where the browser allows it (`appearance: base-select`, Chromium 135 and later): a panel on the select's own ground with a 1px ink frame, square, no shadow; one option per row on a `line` hairline in Archivo 16px; the hovered row, or the keyboard's while the pointer is off the list, inverts on the 240ms curve; the chosen option carries the signal pixel (`on-signal` on a signal sheet); a disabled option is muted, and a placeholder (an empty, disabled first option: *Select*, *Font*, *Size*) names the closed field but is not a row. The closed field keeps its look; it is as wide as its choice, not its longest option, so set a width where the layout needs a fixed one. A Field select is cut before its chevron; any other select (inline in a table or a row) draws the same chevron at its end and is never capped. Firefox and Safari keep the browser's own list, in the ground's colours and the theme's color-scheme. Rules: `bundle.css`, *Select: the open list*.

**Type to filter** (since 2026-11-26, `filter-select`): a reference list too long to scroll or to jump through by first letters (the support portal's State and City, up to 453 cities in a state) is a text field in the same control with the select's chevron, not a select. Typing narrows the list to the entries that contain the text, those that start with it first, then those with a word that does, then the rest; case, accents and extra spaces do not count. The list is the open list above, drawn the same way in every browser (`filter-list`): the field's ground, a 1px ink frame, a row per entry on a hairline, the active row (pointer or arrow keys) inverted on the 240ms curve, the chosen entry marked by the signal pixel before its name; *Nothing matches "…"* in muted text when nothing does. Entering the field selects its text, so typing replaces the choice. ↓ opens and moves, ↑ moves, Enter picks, Escape closes and restores; leaving the field settles on the entry its text names, or the only one it matches, or goes back to the last choice, so the field never posts a name outside the list. The id goes in a hidden input under the field's name. Its empty text says *Type or pick a state*, as a select's says *Select a state*. A name the list carries twice (UAT's two city sets) is offered once, the record's own choice kept. Everywhere else, a native select.

**Switched off**: a control the form disables (a city before its state, a sub category without a category, a field Dynamics field security locks for the signed-in agent) sits at the disabled opacity, label and hint untouched, so it reads as off rather than empty.

**Don't** box the inputs, round them, add icons inside them, or colour the label (only its required asterisk takes the accent). The support and partner portals set their labels at 12px in full ink for reading speed (SupportParts S20); the site's forms keep the muted 11px. Placeholders are examples, not instructions. Error copy says what to fix.

**Build** the `field` and `control` markup from `bundle.css` around native inputs, selects, textareas and checkboxes, never a widget (the one exception is *Type to filter*, `FilterSelect` in `src/components/support`, for lists a select cannot search); the `FormSheet` block renders form-builder documents with it, and the Labs and Support forms use the same markup.
